# 软件工程实践 · 第 5 周

> 目标：模拟真实交付流程，用 Issue、分支、提交说明和发布记录管理一次小版本上线。

## 本周主题

Issue + 分支 + 提交说明 + 发布记录。

## 每周任务

- 为本周版本写 3-5 个 Issue：新增功能、修复问题、体验优化或文档补充。
- 为一个功能建立独立分支，完成后合并回主分支。
- 统一提交说明格式：`feat:`、`fix:`、`docs:`、`style:`、`chore:`。
- 写一份发布记录，说明本版本新增、修复和已知问题。
- 部署版本并保存链接。

## 工程实践

- 每个 Issue 只描述一个明确问题。
- 合并前检查页面、链接、移动端和 README。
- 发布记录要能让别人快速理解这次上线价值。

## 每步更新 GitHub / Vercel

- 开始前：在 GitHub 建好 Issue、分支和本周版本目标。
- 完成一个 Issue：提交、推送并关联 Issue，保持提交记录可追踪。
- 合并前：部署 Vercel 预览，检查功能、链接、移动端和 README。
- 发布后：把 GitHub 版本记录、Vercel 生产链接和已知问题写进发布说明。

## 输出作品

- 一个带版本日志的作品。
- 一组 Issue 或任务记录。
- 一份部署后的发布说明。

## 验收标准

- GitHub 记录能追踪需求、提交和上线过程。
- 发布记录清楚写出版本变化。
- 部署后的作品和 README 中的描述一致。
