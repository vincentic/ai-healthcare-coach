# 软件工程实践 · 第 4 周

> 目标：建立质量意识，把一个已经可用的功能打磨成能复盘、能验收、能继续迭代的版本。

## 本周主题

代码整理 + 边界状态 + 错误提示 + 验收清单。

## 每周任务

- 复查已有页面，把重复逻辑整理成清晰函数。
- 补齐边界状态：空数据、超长文本、快速点击、非法输入、移动端窄屏。
- 优化错误提示和成功反馈，让用户知道操作结果。
- 编写一份手动验收清单。
- 修复至少 3 个体验或稳定性问题。

## 工程实践

- 每个修复都用 `fix:` 或清晰提交信息记录。
- 先复现问题，再修改，再记录验证结果。
- 在复盘中写清楚问题原因和下次避免方式。

## 每步更新 GitHub / Vercel

- 开始前：在 GitHub 列出本周要修复的问题和边界状态。
- 每修复一个问题：用 `fix:` 提交并推送，记录复现方式和验证结果。
- 完成一轮质量检查：部署到 Vercel，在线验证错误提示、空状态和移动端。
- 收尾时：把 GitHub 修复记录、Vercel 链接和验收清单写进复盘。

## 输出作品

- 一个可复盘的功能迭代版本。
- 一份验收清单。
- 一份问题修复记录。

## 验收标准

- 常见边界状态不会破坏页面。
- 用户操作后有明确反馈。
- README 或复盘中能看到质量改进过程。
