# 软件工程实践 · 第 1 周

> 目标：建立稳定的交付节奏，把“学习内容”变成一个能访问、能说明、能持续迭代的个人学习主页 v1。

## 本周主题

Git 基础 + README + 任务拆分 + 静态部署。

## 每周任务

- 明确学习主页要服务的对象：自己复盘、面试展示、朋友查看或长期作品集入口。
- 设计首页的 3-5 个核心模块：学习路线、项目入口、周计划、作品链接、复盘记录。
- 建立 GitHub 仓库结构：`README.md`、`index.html`、模块目录和部署说明。
- 完成至少 3 次有意义的提交，提交信息说明改动目的。
- 部署静态首页，并在 README 中记录访问链接。

## 工程实践

- 每天先写任务清单，再动手改页面。
- 每次提交只解决一个清晰问题。
- 每次部署后检查桌面宽度、手机宽度、导航链接和文案是否正常。

## 每步更新 GitHub / Vercel

- 开始前：在 GitHub 更新本周任务清单，确认 Vercel 当前首页可访问。
- 完成页面结构后：提交并推送到 GitHub，记录本次改动目的。
- 完成样式和导航后：部署到 Vercel，检查桌面和手机宽度。
- 收尾时：把 GitHub 仓库链接、Vercel 链接和本周复盘写进 README。

## 输出作品

- 个人学习主页 v1。
- 一份能说明项目目标和使用方式的 README。
- 一个可公开访问的部署链接。

## 验收标准

- 打开首页后能快速知道你正在学习什么、做了哪些模块。
- GitHub 提交记录能看出持续迭代过程。
- 部署链接可访问，核心链接不报错。
